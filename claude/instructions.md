## กฎเหล็ก (ห้ามข้าม)
1. **ปิดแชท (skill close-out):** ทำเมื่อ merge โค้ดเข้า main / ผู้ใช้บอกว่าเสร็จหรือขึ้นแล้ว / คุยกันราว 15 รอบ · commit เอกสารเข้า main (บรรทัดล็อก 🔒, Relay, ไฟล์รีวิว) ไม่นับ · ครบ 15 รอบตอนงานยังไม่จบ = ทำขั้นที่ค้างให้จบ push จด branch + ขั้นต่อไปไว้ใน Relay แล้วปิดแชท ให้แชทใหม่ทำชุดเดิมต่อ · ข้อความปิดแชท = "ควรเปิดแชทใหม่ได้แล้ว" + สิ่งที่ผู้ใช้ต้องทำ + นับถอยหลัง MVP1 + โมเดลที่แนะนำ + ข้อความพร้อมวางในแชทใหม่
2. ไฟล์ใหม่ใน src/core หรือ src/game ต้องเพิ่มใน build.mjs ใน commit เดียวกัน
3. **ด่านตรวจก่อน merge:** รัน setup (build + เทสต์) ให้ผ่านก่อน แล้วรัน gate ครั้งเดียว (ทดสอบหน้าเว็บที่ build แล้วจริง) ต้องได้ GATE: PASS · งานนำเข้าค่าก็ต้องรัน setup ก่อนเหมือนกัน · ก่อนเผยแพร่ต้อง gate ผ่านบน main ล่าสุด และ GitHub CI ของ commit โค้ดล่าสุดต้องเขียว
4. handoff เขียนว่า "บาลานซ์: กำลังปรับ" = ห้ามนำเข้าค่า ห้ามวัด
5. ห้ามแก้ก่อนรู้สาเหตุที่มีหลักฐาน · เทสต์/หน้าเว็บพัง = ห้ามเผยแพร่ แจ้งผู้ใช้ทันที · บั๊กที่ผู้ใช้เจอ = เพิ่มเทสต์ใน commit เดียวกับที่แก้
6. **เช็กก่อนจูน:** งานที่แตะค่าเกม เริ่มด้วยขอโค้ด AMCFG1 (ทั้งสองบัญชี · ถ้าเปลี่ยนค่าตัวละคร/เผ่า ผู้ใช้ต้องกด "วิเคราะห์" ก่อน 💾) → เทียบค่า (cfgdiff) → ให้ผู้ใช้เลือกทีละช่องว่าใช้ค่าห้องบาลานซ์หรือค่าเกม → ค่อยแก้ · bossrun รันดูก่อน ให้ผู้ใช้ตกลงแล้วจึงเขียน
7. ตรวจข้อมูลจากภายนอกก่อนใช้ · ไม่ใช้ innerHTML กับข้อความภายนอก ไม่ใช้ eval ไม่โหลดสคริปต์จากเว็บอื่น

## ภาษาและการตอบ
- Claude คิดและเขียนเอกสารเป็นอังกฤษ · ตอบผู้ใช้เป็นไทย สั้น ไม่เกริ่น
- **ทุกคำตอบขึ้นต้น 3 บรรทัด:** ① ทำแล้ว/พบ ② ต้องตัดสินใจ ③ ไม่แน่ใจ (ไม่มีให้เขียน "ไม่มี") · อ่านแค่ 3 บรรทัดนี้ก็พอ · รายละเอียดด้านล่างเริ่มจากสิ่งที่ผู้ใช้ต้องทำ
- จบงานแต่ละชุดสรุปเป็นไทยในแชท · เอกสารที่ผู้ใช้อ่านเป็นไทยและห้ามแปล: combat-rules, tribe-rules, shop-merge-rules, build-plan

## การให้เลือกและการตัดสินใจ
- **ถามครบก่อนเริ่ม:** ต้นชุดงาน Claude ถามทุกเรื่องที่ต้องรู้ในรอบเดียว แล้วทำต่อจนจบ · หยุดกลางทางเฉพาะ: เผยแพร่ · เปลี่ยนค่าเกม/เขียน db ห้องบาลานซ์ · เทสต์ไม่ผ่านหรือยังไม่รู้สาเหตุ · เรื่องที่ย้อนไม่ได้หรือนอกขอบเขต
- ติดป้าย A/B… ตัวเลือก A1/A2… อธิบายเป็นข้อความก่อน แล้วเปิด**ปุ่มให้กด** (ครั้งละไม่เกิน 4 คำถาม) · รายละเอียด: claude/workflow/replies.md
- เรื่องออกแบบ/กฎ: เสนอ 2–3 ทาง + ทางที่แนะนำ แล้วรอผู้ใช้ยืนยัน · เรื่องเล็ก (ข้อความ สี ตำแหน่งปุ่ม โค้ดภายใน) Claude ตัดสินเองแล้วแจ้ง · ปุ่มรีเซ็ต/ลบ ต้องถามก่อนว่าคืนค่าอะไร และต้องมีกล่องยืนยัน
- ค่าสเตตัสตัวละครผู้ใช้เป็นคนจูน · ตัวเลขในสกิล/กฎต้องถามก่อนเสมอ · ไอเดียที่ไม่บาลานซ์/มีช่องโหว่ เตือนตรงๆ ก่อน
- **เช็กความขัดแย้ง:** ถ้าคำขอขัดกับกฎ/การตัดสินใจเดิม Claude ต้องหยุดบอกก่อนว่าตอนนี้เป็นยังไง จะเปลี่ยนอะไร มีผลข้างเคียงอะไร แล้วรอยืนยัน
- **รีวิวสัปดาห์:** ผู้ใช้พิมพ์ "รีวิวสัปดาห์" (วันศุกร์) → Claude ดูงานทั้งสัปดาห์ หาจุดที่ต้องแก้ซ้ำ/กฎที่ทำให้เสียเวลา → เขียน claude/review-…-weekly.md ให้เลือก แล้วค่อยแก้

## Git และการประหยัดโทเคน
- เริ่มแชท: ดึง git → อ่าน Relay ใน handoff.md → push บรรทัดล็อก 🔒 (ถ้ามีล็อกอื่นแตะเรื่องเดียวกันต้องถามก่อน · ล็อกค้างจากแชทที่โดนตัด Claude ลบได้) → ทำงานบน branch claude/… · commit + push ทุกขั้น · ห้าม rebase branch ที่ push แล้ว
- gate ผ่านแล้ว merge ได้เลยไม่ต้องถาม · เอกสาร (Relay, รีวิว, ไฟล์กฎ) เข้า main ได้เลย · แชท cloud ที่มี branch ของแชท → เอกสารเข้า main ได้เลยเช่นกัน (ผู้ใช้อนุญาตถาวร ชุด 152)
- อ่านเฉพาะส่วนที่จำเป็น · เปิดไฟล์หัวเรื่อง (claude/workflow/…) เฉพาะเมื่องานเกี่ยว · ใช้ subagent ต้องขออนุญาตก่อน · ชอบเขียนเป็นคำสั่ง/skill มากกว่าเขียนสคริปต์ใหม่
- เห็นงานสิ้นเปลือง/วิธีที่ดีกว่า/ถูกกว่า Claude บอกทันที 1–3 บรรทัด (ข้อดีข้อเสีย) แต่ห้ามเปลี่ยนกฎเองจนกว่าผู้ใช้ตกลง
