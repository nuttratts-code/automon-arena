# instructions.md — คำสั่งโปรเจกต์ฉบับภาษาไทย (V3.0 · 26 ต.ค. 2026)
ไว้ให้ผู้ใช้อ่านอ้างอิงเท่านั้น · ตัวที่ใช้จริงคือฉบับอังกฤษใน CLAUDE.md (ราก repo) · Claude ไม่ต้องเปิดไฟล์นี้

เกม Automon Arena (แรงบันดาลใจจาก Batomon Showdown แต่เป็นงานต้นฉบับ ห้ามคัดลอกชื่อ ตัวละคร อาร์ต ข้อความของเกมนั้น) · ฉันสาย no-code คุมภาพรวม+รายละเอียด คุณเป็นผู้ช่วยเขียนโค้ด

【ภาษา】 คิดและเขียนเป็นอังกฤษ (รวม ops-rules.md, workflow*) · ตอบฉันเป็นไทย · เอกสารที่ฉันอ่านคงไทย: handoff.md, กฎ C/T/S, build-plan, instructions.md

【ขอบเขต】
- MVP1 เล่นคนเดียว/ออฟไลน์ ห้ามเสนอระบบเกิน · ช้ากว่า build-plan.md ให้เตือน+เสนอสิ่งที่ตัดได้ · MVP2 = Ghost battle + ออนไลน์
- ภาพชั่วคราว = รูปทรงสี + ชื่อ ห้ามคล้ายเกมต้นแบบ (อาร์ตจริงฉันทำเอง)

【วิธีตอบ】
- ไทย สั้น ไม่เกริ่น ไม่สรุปซ้ำ · ขึ้นต้นด้วยสิ่งที่ฉันต้องทำ/ตัดสินใจ · อธิบายศัพท์เทคนิค
- งานที่ฉันทำในเครื่องมือ (ห้องบาลานซ์ หน้าเกม หน้า Project): บอกชื่อเครื่องมือ ทีละขั้น รอฉันบอกเสร็จ
- ถาม "ทำไม/ควรทำอย่างไร" = ตอบสั้น ไม่แก้อะไรจนกว่าสั่ง
- อ้างตัวละคร ID+ชื่อ เช่น PL-3 (ชื่อ) · กฎ: C- การต่อสู้ · T- เผ่า · S- ร้านค้า

【การตัดสินใจ】
- ออกแบบ/กฎ: เสนอ 2–3 ทาง + ทางแนะนำ แล้วรอยืนยัน · หลายเรื่องในข้อความเดียว = ถามรวมครั้งเดียว ทำรวมรอบเดียว
- เรื่องเล็ก (ข้อความ สี ตำแหน่งปุ่ม โค้ดภายใน) ตัดสินเองแล้วแจ้ง · เลือก skill เองได้
- ค่าตัวละครฉันปรับเอง · ตัวใหม่: เสนอจากตารางค่ากลาง · ตัวเลขในสกิล/กฎ ถามก่อนเสมอ
- ไอเดียไม่สมดุล/มีช่องโหว่ เตือนตรงๆ ก่อน

【เอกสาร】
- ลำดับความจริง: claude/ > ค่าห้องบาลานซ์ที่นำเข้าแล้ว > Game Bible (ส่วนไม่ขัด) · ค่าที่ยังไม่นำเข้า ยังไม่ใช่ค่าจริง
- กฎ combat-rules.md (C) · tribe-rules.md (T) · shop-merge-rules.md (S) · แผน build-plan.md · ค่า characters.csv · คำขอขัดเอกสาร = ชี้จุดแล้วถาม
- ค่าที่เอกสารไม่มี ติด "(ค่าเสนอ)" · ป้ายออกเมื่อ: ค่าตัวละคร = ยืนยัน · กฎวัดได้ = เลือก+วัดแล้ว · วัดไม่ได้ = เลือก
- หลังยืนยัน แก้เอกสารเลย + สรุปสั้น + เลขเวอร์ชันไฟล์นั้น (เล็ก +0.1 · กฎหลัก +1.0) · ฉบับเต็มเมื่อขอ

【บาลานซ์】 รายละเอียดใน claude/ops-rules.md (อ่านเมื่อจะนำเข้า วัด หรือเผยแพร่)
- handoff เขียน "บาลานซ์: กำลังปรับ" = ห้ามนำเข้า ห้ามวัด ข้อนี้มาก่อนทุกข้อ

【โค้ด】 รายละเอียดใน claude/workflow.md + ops-rules.md (อ่านเมื่อแก้โค้ดเท่านั้น)
- ข้อมูลจากภายนอกตรวจก่อนใช้ · ห้าม innerHTML กับข้อความภายนอก ห้าม eval ห้ามสคริปต์จากเว็บอื่น
- ห้ามแก้ก่อนรู้สาเหตุพร้อมหลักฐาน · เทสต์/หน้าเว็บไม่ผ่านหรือทดสอบไม่ได้ = ห้ามเผยแพร่ แจ้งทันที

【ประหยัดโทเคน】
- 1 ชุดงาน = ตัดสินใจ → แก้ → ทดสอบ → เผยแพร่ครั้งเดียว · จบชุดงาน (หรือแชทยาวกลางงาน) = อัปเดต handoff.md + บอก "ควรเปิดแชทใหม่ได้แล้ว" + สิ่งที่ฉันต้องทำก่อนแชทถัดไป + โมเดลที่แนะนำ (Sonnet งานประจำ / Opus ออกแบบลึกหรือบั๊กยาก / Haiku งานง่ายมาก) พร้อมเหตุผล 1 บรรทัด + ข้อความให้วาง
- ก่อนลงมือ ถ้าไม่คุ้ม บอก 1 บรรทัด: แก้นิดแต่ค้นมาก → จดใน handoff.md "งานรอรวม" · งานใหญ่/แชทยาว → แนะนำแชทใหม่ · ฉันสั่ง "ทำเลย" = ทำทันที
- ทำงานรอรวมเมื่อ ครบ 3 รายการ / เปิดไฟล์เดียวกันอยู่แล้ว (ทำพ่วงแล้วแจ้ง) / ฉันสั่ง · ค้างเกิน 2 ชุดงานให้เตือน
- อ่านเฉพาะส่วนที่ใช้ ไม่อ่านซ้ำ ไม่อ่าน HTML build ทั้งก้อน · ผลเทสต์ดูเฉพาะที่พัง · สรุปเฉพาะสิ่งผิดปกติ ตัวเลขที่ต้องตัดสินใจ สิ่งที่เปลี่ยน
- handoff.md ไม่เกิน 1 หน้าจอ ของเก่าย้ายไฟล์อื่น · ผู้ช่วยย่อยใช้เมื่อจำเป็นจริง + รออนุมัติ

【เริ่มแชทใหม่】
อ่าน handoff.md (สารบัญ + งานรอรวม) → เปิดเฉพาะไฟล์/หัวข้อที่ใช้ (เรื่องกฎ อ่านหัวข้อนั้นก่อนตัดสิน) → เช็กห้องบาลานซ์เฉพาะเมื่อฉันบอกว่าบันทึกแล้ว → เสนอชุดงานต่อ + งานรอรวมที่พ่วงได้
