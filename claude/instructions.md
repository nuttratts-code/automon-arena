【กฎเหล็ก — อ่านก่อน ห้ามข้าม】
0. บอกแผนก่อน รอฉันตกลง (ผู้ใช้สั่ง 8 พ.ย. ชุด 137): ก่อนแก้อะไรทุกอย่าง (โค้ด เอกสาร ค่า ข้อมูลห้องบาลานซ์ รวมเข้า main เผยแพร่) ต้องบอกสาเหตุ (พร้อมหลักฐาน) + จะแก้อะไร + ฉันจะเห็นอะไรหลังแก้ แล้วหยุดรอฉันตกลง · การค้นหาสาเหตุที่ไม่แก้อะไร (อ่านโค้ด ดูฐานข้อมูล) ทำก่อนได้ · แผนที่ฉันตกลงแล้วครอบคลุมการรวมเข้า main + เผยแพร่หลังผ่านด่านตรวจ ไม่ต้องถามซ้ำ · เรื่องเล็กก็ต้องเสนอตัวเลือกให้ฉันเลือก
1. ปิดแชท: ทุกครั้งที่รวมเข้า main / ฉันบอกว่าเสร็จหรือขึ้นเว็บแล้ว / คุยในแชทเดียวราว 15 รอบ → อัปเดต handoff.md + push แล้วบอก "ควรเปิดแชทใหม่ได้แล้ว" + สิ่งที่ฉันต้องทำก่อน + โมเดลที่แนะนำ + ข้อความให้วางในแชทใหม่ (ตัวเลือกงานถัดไปอยู่ในข้อความนั้น) · ห้ามเริ่มงานใหม่ในแชทเดิม
2. ไฟล์ใหม่ใน src/core หรือ src/game ต้องเพิ่มใน CORE ของ src/build.mjs ใน commit เดียวกัน
3. ด่านก่อนรวม/เผยแพร่: รันเทสต์ย่อย `cd src && node tools/bootstrap.mjs setup` ให้ผ่านก่อนเสมอ แล้วค่อยตรวจรวมครั้งเดียว (ผู้ใช้สั่ง 5 พ.ย.) · รัน `cd src && node tools/bootstrap.mjs gate` ต้องได้ GATE: PASS (build + เทสต์ + ทดสอบหน้าเว็บที่ build แล้ว) · GitHub Actions รันด่านเดียวกันทุกครั้งที่ push · แชทที่เผยแพร่ต้องดึง main ล่าสุดแล้วผ่านด่านอีกครั้ง · ทดสอบไม่ได้ = บอกฉันแล้วรอ ห้ามรวม/เผยแพร่เงียบๆ
4. handoff.md เขียน "บาลานซ์: กำลังปรับ" = ห้ามนำเข้า ห้ามวัด (มาก่อนทุกข้อ)
5. ห้ามแก้ก่อนรู้สาเหตุพร้อมหลักฐาน · เทสต์/หน้าเว็บไม่ผ่านหรือทดสอบไม่ได้ = ห้ามเผยแพร่ แจ้งทันที

【วิธีตอบ】
- ไทย สั้น ไม่เกริ่น ไม่สรุปซ้ำ · ขึ้นต้นด้วยสิ่งที่ฉันต้องทำ/ตัดสินใจ · อธิบายศัพท์เทคนิค
- งานที่ฉันทำในเครื่องมือ (ห้องบาลานซ์ หน้าเกม หน้า Project): บอกชื่อเครื่องมือ ทีละขั้น รอฉันบอกเสร็จ
- ถาม "ทำไม/ควรทำอย่างไร" = ตอบสั้น ไม่แก้อะไรจนกว่าสั่ง
- อ้างตัวละคร ID+ชื่อ เช่น PL-3 (ชื่อ) · กฎ: C- การต่อสู้ · T- เผ่า · S- ร้านค้า

【การตัดสินใจ】
- ออกแบบ/กฎ: เสนอ 2–3 ทาง + ทางแนะนำ แล้วรอยืนยัน · หลายเรื่องในข้อความเดียว = ถามรวมครั้งเดียว ทำรวมรอบเดียว
- เรื่องเล็ก (ข้อความ สี ตำแหน่งปุ่ม โค้ดภายใน) เสนอ 2–3 ทาง + ทางแนะนำ แล้วรอฉันเลือก (ชุด 137) · เลือก skill เองได้
- ค่าตัวละครฉันปรับเอง · ตัวใหม่: เสนอจากตารางค่ากลาง · ตัวเลขในสกิล/กฎ ถามก่อนเสมอ
- ไอเดียไม่สมดุล/มีช่องโหว่ เตือนตรงๆ ก่อน

【เอกสาร】

- กฎ combat-rules.md (C) · tribe-rules.md (T) · shop-merge-rules.md (S) · แผน build-plan.md · ค่า characters.csv · คำขอขัดเอกสาร = ชี้จุดแล้วถาม

- หลังยืนยัน แก้เอกสารเลย + สรุปสั้น + เลขเวอร์ชันไฟล์นั้น (เล็ก +0.1 · กฎหลัก +1.0) · ฉบับเต็มเมื่อขอ

【ประหยัดโทเคน】
- 1 ชุดงาน = ตัดสินใจ → แก้ → ทดสอบ → เผยแพร่ครั้งเดียว · จบชุดงาน (หรือแชทยาวกลางงาน) = อัปเดต handoff.md + บอก "ควรเปิดแชทใหม่ได้แล้ว" + สิ่งที่ฉันต้องทำก่อนแชทถัดไป + โมเดลที่แนะนำ (Sonnet งานประจำ / Opus ออกแบบลึกหรือบั๊กยาก / Haiku งานง่ายมาก) พร้อมเหตุผล 1 บรรทัด + ข้อความให้วาง
- ก่อนลงมือ ถ้าไม่คุ้ม บอก 1 บรรทัด: แก้นิดแต่ค้นมาก → จดใน handoff.md "งานรอรวม" · งานใหญ่/แชทยาว → แนะนำแชทใหม่ · ฉันสั่ง "ทำเลย" = ทำทันที
- ทำงานรอรวมเมื่อ ครบ 3 รายการ / เปิดไฟล์เดียวกันอยู่แล้ว (ทำพ่วงแล้วแจ้ง) / ฉันสั่ง · ค้างเกิน 2 ชุดงานให้เตือน
- อ่านเฉพาะส่วนที่ใช้ ไม่อ่านซ้ำ ไม่อ่าน HTML build ทั้งก้อน · ผลเทสต์ดูเฉพาะที่พัง · สรุปเฉพาะสิ่งผิดปกติ ตัวเลขที่ต้องตัดสินใจ สิ่งที่เปลี่ยน
- handoff.md ไม่เกิน 1 หน้าจอ ของเก่าย้ายไฟล์อื่น · ผู้ช่วยย่อยใช้เมื่อจำเป็นจริง + รออนุมัติ

【Git และสองบัญชี】
- แก้บน branch `claude/<หัวข้อ>` · รวมเข้า main ได้ทันทีเมื่อผ่านด่าน (GATE: PASS) ไม่ต้องถามฉัน (กฎ 2 พ.ย.) · ไม่ผ่าน/รันไม่ได้ = ห้ามรวม แจ้งฉัน · commit + push ทุกขั้นตอนสำคัญ
- สองบัญชี Claude ผลัดกันทำ ทีละบัญชี · บล็อก "Relay" บนสุดของ handoff.md (อยู่บน main เสมอ) บอกว่าใครทำอะไรค้าง ขั้นต่อไปคืออะไร
- หน้าเว็บ (เกม/ห้องบาลานซ์/หน้าเช็ก) เป็นของบัญชีแรก · บัญชีที่สองเผยแพร่ไม่ได้ → เขียน "publish pending" + ให้ข้อความฉันไปวางในแชทเก่าที่เปิดจากห้องบาลานซ์ (ตัดสิน 31 ต.ค.) · ห้ามสร้างหน้าใหม่ (ลิงก์เปลี่ยน ข้อมูลห้องบาลานซ์หาย)
- ค่าและไอเดียจากห้องบาลานซ์ส่งถึง Claude ทางรหัส AMCFG1 ("คัดลอกค่าให้ Claude") เท่านั้น
