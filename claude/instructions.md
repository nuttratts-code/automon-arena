## กฎเหล็ก (ห้ามข้าม)
1. **ปิดแชท (skill close-out):** ทำเมื่อ merge โค้ดเข้า main / ผู้ใช้บอกว่าเสร็จหรือขึ้นแล้ว / คุยกันราว 15 รอบ · commit เอกสารเข้า main (บรรทัดล็อก 🔒, Relay, ไฟล์รีวิว) ไม่นับ · ครบ 15 รอบตอนงานยังไม่จบ = ทำขั้นที่ค้างให้จบ push จด branch + ขั้นต่อไปไว้ใน Relay แล้วปิดแชท ให้แชทใหม่ทำชุดเดิมต่อ · ก่อนปิดแชท Claude ดูว่างานในแชทนี้ควรเก็บเป็นสกิลไหม (ทำซ้ำ + หลายขั้น + เคยพลาด) ถ้าควร ถามผู้ใช้ A1 จดเป็นสกิล / A2 แก้ไฟล์เดิม / A3 ไม่ต้อง · ข้อความปิดแชท = "ควรเปิดแชทใหม่ได้แล้ว" + สิ่งที่ผู้ใช้ต้องทำ + นับถอยหลัง MVP1 + โมเดลที่แนะนำ + ข้อความพร้อมวางในแชทใหม่
2. ไฟล์ใหม่ใน src/core หรือ src/game ต้องเพิ่มใน build.mjs ใน commit เดียวกัน
3. **ด่านตรวจก่อน merge:** รัน setup (build + เทสต์) ให้ผ่านก่อน แล้วรัน gate ครั้งเดียว (ทดสอบหน้าเว็บที่ build แล้วจริง) ต้องได้ GATE: PASS · งานนำเข้าค่าก็ต้องรัน setup ก่อนเหมือนกัน · ก่อนเผยแพร่ต้อง gate ผ่านบน main ล่าสุด และ GitHub CI ของ commit โค้ดล่าสุดต้องเขียว
4. handoff เขียนว่า "บาลานซ์: กำลังปรับ" = ห้ามนำเข้าค่า ห้ามวัด
5. ห้ามแก้ก่อนรู้สาเหตุที่มีหลักฐาน · เทสต์/หน้าเว็บพัง = ห้ามเผยแพร่ แจ้งผู้ใช้ทันที · บั๊กที่ผู้ใช้เจอ = เพิ่มเทสต์ใน commit เดียวกับที่แก้
6. **เช็กก่อนจูน:** งานที่แตะค่าเกม เริ่มด้วยโค้ด AMCFG1 (บัญชีหลัก: ผู้ใช้กด 💾 แล้วบอก Claude ดึงค่าจากห้องบาลานซ์เองไม่ต้องวางโค้ด · บัญชีที่ 2: ผู้ใช้วางโค้ด · ชุด 166 · ถ้าเปลี่ยนค่าตัวละคร/เผ่า ผู้ใช้ต้องกด "วิเคราะห์" ก่อน 💾) → เทียบค่า (cfgdiff) → ให้ผู้ใช้เลือกทีละช่องว่าใช้ค่าห้องบาลานซ์หรือค่าเกม → ค่อยแก้ · bossrun รันดูก่อน ให้ผู้ใช้ตกลงแล้วจึงเขียน
7. (ส่วนหนึ่งของกฎข้อ 9) ตรวจข้อมูลจากภายนอกก่อนใช้ · ไม่ใช้ innerHTML กับข้อความภายนอก ไม่ใช้ eval ไม่โหลดสคริปต์จากเว็บอื่น
8. **ตรวจจุดที่ต้องแก้ตาม (ripple check, ชุด 186):** ก่อน commit ทุกครั้งที่เปลี่ยนการทำงาน ค่า ชื่อ ข้อความที่ผู้เล่นเห็น รูปแบบเซฟ หรือกฎ ให้ค้นคำที่เปลี่ยน (รวมชื่อเก่า) ในโค้ด เอกสาร เทสต์ และหน้าอื่นๆ แล้วไล่ตามแผนที่ใน claude/workflow/ripple.md · แก้ทุกจุด หรือบอกเหตุผลที่ไม่แก้ · จดบรรทัด `ripple:` ไว้ใน commit ที่รวมโค้ดเข้า main (หรือ commit เดี่ยวที่แก้เอกสาร/ค่า) · commit ระหว่างทำ/งานตัวอย่างไม่ต้องจด (ชุด 218) · รีวิวสัปดาห์จะดูว่าจุดที่หลุดมาจากแถวไหนแล้วเติมแผนที่
9. **ความปลอดภัยทุกขั้นตอน (ชุด 190 · ผู้ใช้เลือก C1 เพราะมีคนโดนขโมย/โจมตีผลงานเยอะ):** ① ห้ามมีรหัสลับ (API key รหัสผ่าน โทเคน) ใน repo commit เอกสาร หรือแชท — ใส่ผ่านฟอร์มปลอดภัยเท่านั้น และค้นหารหัสลับก่อน commit ทุกครั้ง ② ห้ามใช้โค้ด ปลั๊กอิน แพ็กเกจ ภาพ เสียง ฟอนต์จากที่อื่น ถ้ายังไม่เช็คแหล่งที่มา + สัญญาอนุญาต + เครดิต และผู้ใช้ยังไม่ตกลง ③ ตรวจข้อมูลจากภายนอกทุกครั้งก่อนใช้ (กฎข้อ 7) ④ ไฟล์เกมที่ปล่อยให้เล่นมีแค่ตัวเกม ไม่มีเอกสาร เครื่องมือ เทสต์ ข้อมูลดีบัก · Godot ส่งออกแบบ release + เข้ารหัสไฟล์เกม กุญแจไม่อยู่ใน repo ⑤ เปิดยืนยันตัวตน 2 ชั้น (2FA) ทุกบัญชี GitHub itch.io Google · repo เป็นส่วนตัว ⑥ ทุกขั้นในแผนงานต้องมีบรรทัดความปลอดภัย · รายละเอียด: claude/workflow/security.md · ไฟล์ LICENSE = สงวนลิขสิทธิ์ทั้งหมด

- **เช็กความขัดแย้ง:** ถ้าคำขอขัดกับกฎ/การตัดสินใจเดิม Claude ต้องหยุดบอกก่อนว่าตอนนี้เป็นยังไง จะเปลี่ยนอะไร มีผลข้างเคียงอะไร แล้วรอยืนยัน

## Git และการประหยัดโทเคน
- เริ่มแชท: ดึง git → อ่าน Relay ใน handoff.md → push บรรทัดล็อก 🔒 (ถ้ามีล็อกอื่นแตะเรื่องเดียวกันต้องถามก่อน · ล็อกค้างจากแชทที่โดนตัด Claude ลบได้) → ทำงานบน branch claude/… · commit + push ทุกขั้น · ห้าม rebase branch ที่ push แล้ว
- gate ผ่านแล้ว merge ได้เลยไม่ต้องถาม · เอกสาร (Relay, รีวิว, ไฟล์กฎ) เข้า main ได้เลย แต่ต้องส่งจากสำเนา main ที่สะอาดเท่านั้น ห้ามส่งทั้งสาขางานเข้า main (ชุด 218 — ชุด 217 สาขาตัวอย่างหลุดเข้า main) · ก่อน push เช็คว่าไม่มีไฟล์ค้างและไฟล์ครบ · แชท cloud ที่มี branch ของแชท → เอกสารเข้า main ได้เลยเช่นกัน (ผู้ใช้อนุญาตถาวร ชุด 152)
- อ่านเฉพาะส่วนที่จำเป็น · เปิดไฟล์หัวเรื่อง (claude/workflow/…) เฉพาะเมื่องานเกี่ยว · ใช้ subagent ต้องขออนุญาตก่อน · ชอบเขียนเป็นคำสั่ง/skill มากกว่าเขียนสคริปต์ใหม่
- เห็นงานสิ้นเปลือง/วิธีที่ดีกว่า/ถูกกว่า Claude บอกทันที 1–3 บรรทัด (ข้อดีข้อเสีย) แต่ห้ามเปลี่ยนกฎเองจนกว่าผู้ใช้ตกลง
- สกิลที่มี: close-out (ปิดแชท) · weekly-review (รีวิวสัปดาห์/ตรวจ workflow) · balance-import (นำเข้าค่าจาก AMCFG1 ทีละขั้น) · publish-pages (เผยแพร่หน้าเว็บทีละขั้น) · chat-start (เริ่มแชท: Relay · 🔒 · สาขา) · merge-code (setup → gate → merge → CI) · rule-change (เปลี่ยนกฎ: เช็กขัด → ตัวเลือก → แก้เอกสาร + เวอร์ชัน) · measure-balance (Claude วัดบาลานซ์เมื่อผู้ใช้สั่ง) · ui-work (งานหน้าจอ: ถามก่อน → สกิลออกแบบ → ภาพหน้าจอคอม+มือถือ; merge-code เช็กซ้ำ) · ui-preview (ทำภาพตัวอย่างหน้าจอทีละรอบ ยังไม่แก้โค้ดจริง · ถ้าผู้ใช้จัดฉากเองใน Godot ใช้สาขาตัวอย่าง ห้าม merge) · ui-patterns (เทียบดีไซน์กับเกมอื่น หาจุดที่ดูเหมือน AI ทำ) · art-look (หน้าตาฉากสู้: สไปรต์พิกเซลในฉาก 3D แสง เบลอ) · asset-3d (ทำพร็อพ 3D: รูป Gemini → เว็บ AI 3D → Blender → วางในฉาก) · find-cause (หาสาเหตุก่อนแก้บั๊ก) · brainstorm (ระดมสมองผู้เชี่ยวชาญจำลอง) · sim-play (Claude เล่นเกมเว็บจำลองหาบั๊ก) · godot-play (Claude เล่นเกม Godot หาบั๊ก ฉบับร่าง) · port-parity (เช็คว่า Godot ให้ผลตรงกับเกมเว็บ) · godot-release (ทำไฟล์เกมขึ้น itch.io) · ci-check (ดูผล CI บนคอมผู้ใช้) · ตอนเริ่มแชทระบบ (hook) แสดง Relay ให้อัตโนมัติ
