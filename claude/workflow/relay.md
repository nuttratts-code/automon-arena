# workflow · relay between two accounts + publish ownership

V1.5 · 12 Nov 2026 (set 211 B1: open WIP sets stay in the Relay) · V1.4 · 8 Nov 2026 (set 158: points to skill chat-start) · V1.3 · 8 Nov 2026 (set 153 F1: lock line also in CLAUDE.md start of chat) · V1.2 · 8 Nov 2026 (set 152 audit: archive path · stale lock · docs to main · session branch) · V1.1 · 8 Nov 2026 (set 151 review W2 lock line + W3 no rebase) · V1.0 set 139: moved out of CLAUDE.md — decisions 27 Oct, 30 Oct, set 59. Open when the task involves: starting from a WIP branch, publishing an artifact, the other account, or updating the Relay block.

Step-by-step runbook: skill `.claude/skills/chat-start/SKILL.md` (set 158). This file holds the rules and wins if they differ; when a rule here changes, update the skill in the same commit.

Two Claude accounts take turns on this repo: when one hits its usage limit, the other picks up. Only ONE account works at a time.

- **Start of every chat:** `git fetch origin` → check the "Relay" block at the top of claude/handoff.md → if it names an open WIP branch, check it out and continue from "Next step"; otherwise branch from latest main.
- **Lock line against parallel chats (review W2, set 151):** right after reading the Relay, push to main (docs-only) one line at the top of the Relay block: `🔒 set N · <topic> · files/areas: …` (N = highest set number on main + 1). If another 🔒 line already touches the same files/areas, game values or the Balance Room db → stop and ask the user before starting. Close-out removes your own line. cfgdiff / import always runs against `origin/main` fetched at that moment. **Stale lock (set 152 E-b):** a 🔒 line whose set has no open WIP branch on origin and no newer commit than the last Relay set entry is left over from a chat cut by the usage limit → remove it with a one-line note in the Relay, no need to ask.
- **Relay block always lives on main (decision 27 Oct):** every Relay update is also committed to main right away (docs-only commit: handoff.md, review/report files, and rule docs — CLAUDE.md, claude/workflow*, .claude/skills — set 152 E-d; no code). Reports/lists the user must pick from go in a file under claude/ (e.g. claude/review-YYYY-MM-DD.md) named in the Relay block — never only in chat. If main's Relay looks stale, also check `git ls-remote origin 'refs/heads/claude/*'` for newer branches.
- **Relay size (set 139):** the Relay keeps only the newest 2 sets + any set still open as WIP (set 211 B1: it stays until its own close-out) + open decisions + current publish versions; older entries go to claude/archive/relay/relay-*.md at every close-out.
- **While working:** commit + push after every meaningful step (a limit can cut the chat at any moment; unpushed work is lost). Branch name: `claude/<topic>`. Never force-push; never rewrite another account's commits. **Never rebase a branch that is already pushed (review W3, set 151 — set 139 duplicated commits on main): push rejected → `git fetch` + `git merge origin/<branch>` (or origin/main), then push.**
- **Before stopping / when the chat feels long / at end of set:** update the Relay block (account, branch, last done, next step, open decisions) and push. Merge to main once GATE: PASS (no user OK needed, rule 2 Nov).
- **Finding the artifacts:** they are shared from the other account, so `Artifact list` (any scope) does NOT show them. Always open them by URL from the "Links" section of claude/handoff.md (`Artifact read` with that url) — never conclude "no access" from an empty list.
- **Published artifacts** (game / balance room / check) are owned by the original account. The other account may update them only if they were shared with edit access ("writer" in an Artifact read); otherwise do not publish — note "publish pending" in the Relay block for the owner account.
- **Publish workflow (decision 30 Oct, updated set 59):** after merging to main, first try to publish from the current chat: `Artifact read` the Links URL — if the header says "writer", publish with the Artifact tool (`file_path` = built src/*.html, `url` = Links URL), then update the Relay block (version + time) on main. Only if the read says "not found"/not writer: tell the user to paste in the old chat opened FROM the Balance Room page: `git fetch แล้วรัน cd src && node tools/bootstrap.mjs gate ต้องได้ GATE: PASS ถ้าไม่ผ่านห้าม publish แล้ว publish <artifact> จาก main (<set>) จากนั้นแก้ Relay ใน claude/handoff.md ว่า publish เสร็จแล้ว (เลขเวอร์ชัน + เวลา + GATE PASS) แล้ว commit + push เข้า main (แก้แค่ handoff.md) ไม่ต้องทำอย่างอื่น ตอบสั้นเป็นภาษาไทย`, and note "publish pending" in the Relay block until that chat clears it; the next chat trusts the Relay block and does not ask the user whether publish was done. Do not create a new copy of an artifact (link changes, Balance Room data is lost).
- **Cloud sessions with an assigned session branch (set 152 E-e):** if the session instructions allow pushing only to that branch, push to that branch AND push docs-only commits to main too — the user allowed this for all such chats (set 152 E1, standing permission). Code still reaches main only by merge after GATE: PASS — that merge + push to main is also allowed from a cloud session (user D1, set 180; no need to ask again).
- Balance Room data (ArtifactData) lives in the artifact, not git: same ownership rule.
- Publish mechanics (gate first, build from latest main, don't read built HTML): claude/workflow/publish.md §3.
