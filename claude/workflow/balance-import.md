## 00. Check before tuning (V1.32, user rule set 130 · CLAUDE.md HARD RULE 6) — before ANY work that touches game values
1. Get a fresh AMCFG1 (user rule set 166 — replaces set 152 E-c "paste for both accounts"):
   - **Main account** (`Artifact read` of the Balance Room Links URL says "writer" and `ArtifactData` can read `config/main`): do NOT ask for a paste. The user only presses 💾 and says so (Claude sees saved values only, never unsaved edits in the browser). Read `config/main` + `results/latest` + the `ideas` collection, then build the same code the page's "คัดลอกค่าให้ Claude" button builds (src/lab/balance/js/70-persist.js): `AMCFG1 ` + JSON `{v:1, config:<config/main>, measured:{at, edits} of results/latest or null, ideas:[open ideas (status รอ Claude / ต้องเลือกก่อน), max 50]}` → save to the scratchpad as `amcfg.txt`. Every tool below runs on it unchanged.
   - **2nd account** (no writer / db read fails): ask the user for the paste (Balance Room → 💾 → "คัดลอกค่าให้ Claude"), save it to the scratchpad.
2. `cd src && node tools/cfgdiff.mjs <file> --md ../claude/review-YYYY-MM-DD-cfgdiff-revNN.md` (NN = AMCFG1 rev, so two runs on one day do not collide) → lists ONLY differing cells across chars · tribe bonuses · game rules · runes · custom runes · bosses (every phase) · mode settings (แท็บด่าน). MATCH = go on. (Chars/tribes/rules in the code are only the fields the user changed vs the page defaults; the page defaults = game only if the Balance Room was published from the current main — check the Relay publish line.)
3. DIFFERS → commit the review file to main (docs-only) and ask the user in Thai, per cell or per group: **ยึด Balance Room** (import it) or **ยึดเกม** (keep the game; user sets it back on the page). Wait for the answer. Never pick a side yourself.
4. Do the work: Balance Room side → chars/tribes/rules: tools/apply-config.mjs (§0) · stage: `node tools/apply-stage.mjs <out>/main.json --take <part | part:id,…>` (e.g. `bosses:B1,runes:T2,settings:foeFloor`) → re-run cfgdiff: the taken cells must be gone.
4b. **After an import that renames or changes runes/characters (review W6, set 151 — sets 131 and 146 failed the first gate):** `grep -n` each changed id/name in src/tests/ui_smoke.py and fix it BEFORE `setup` / `gate`.
5. **Boss values (set 170: bossrun has no --write; the old mult10/endlessPct tuning is gone): `node lab/bossrun.mjs … --fit --md <file>` is a report only → show the user the before → after table (power, hp, atk, phase atk, weak %, resist %, g, a, win %) → write only the cells the user picks, with tools/apply-stage.mjs** (or a hand edit of stage-user.js boss2 for g/a).
6. After the merge: publish the Balance Room (page defaults = game) and tell the user, cell by cell, what they must set back on the page (the "ยึดเกม" cells + any values Claude changed, e.g. bossrun) and press 💾 — otherwise their saved config still holds the old values and the next import reverts them.

## 0. Fast import order (V1.31, user 5 Nov: fastest without losing any check · ~20 min instead of ~30)
Heavy jobs run ONE at a time (2 cores), always in the background; do the light work while each one runs. Never skip a step below.
1. Input = an AMCFG1 code (§00 step 1: main account builds it from the db, 2nd account pastes it; set 166) → `tools/cfgcode.mjs` → pre-import check (edits.chars/tribes/rules == config) + §00 cfgdiff. Config `stage` (runes/bosses/mode settings) is imported item by item with tools/apply-stage.mjs for every cell the user chose "ยึด Balance Room" in §00 (V1.32 — before set 130 the stage tab was never imported, so the page and the game drifted apart).
2. Copy core/characters.js to `core/characters.before.js` (inside core/ so its imports resolve) → `node tools/apply-config.mjs <main.json>` → `node tools/csv.mjs core/characters.before.js` → move `src/characters.csv` to `claude/characters.csv` → delete the .before copy.
3. **Do not run the full test suite here** (it fails anyway until bot teams are rebuilt). Grep tests for the changed IDs (`grep -n "'ID'" tests/*.js`), fix tests on changed kits (old kit → retired test `ID@n` in SC_OLD/SC_RETIRED), check only them: `node tools/bootstrap.mjs test <ID>` (seconds). Commit + push.
4. Background: `node lab/botgen.mjs 2400 4` (botteams.md §13; ~6.5–13 min, not re-timed since set 99). Meanwhile: draft the handoff Relay line, `Artifact read` the 3 Links URLs (writer check).
5. Bosses affected → background `node lab/bossref.mjs 600 300` if lab/bossref.json is stale, then `node lab/bossrun.mjs 600 75 62 50 --fit --md <file>` (report only) → show the user before → after (§00 step 5) → write only the picked cells. Commit + push.
6. `node tools/bootstrap.mjs setup` until it passes (HARD RULE 3, set 152 D1 — fix every failure here, never in the gate).
6b. Background: `node tools/bootstrap.mjs gate` ONCE (~4 min after a passing setup; longer if unit tests re-run). Meanwhile: finish handoff text.
7. GATE: PASS → fast-forward main → publish the 3 pages in parallel → clear config/main (chars/tribes {}, bump rev + savedAt, appliedAt/appliedNote; remove stale `stage` only if it is older than the game's) → push Relay to main → tell the user the cells to set back (§00 step 6).

## 8. Balance Room (ArtifactData)
- **Read only when the user says they saved** · if handoff says "บาลานซ์: กำลังปรับ" do not import.
- config/main: values the user saved with "บันทึกให้ Claude" (diff from defaults) → import into characters.js/rules.js → test → read results/latest and run the 2 checks of measure.md step 0 (do not measure yourself · outliers pass) → update docs → clear to `{chars:{}, tribes:{}, appliedAt, appliedNote}`.
- **Pre-import check (V1.27; only when character or tribe values changed — set 153 I1; cfgcode DIFFERS on a runes/bosses/rules-only import is not a blocker):** compare results/latest `edits.chars` and `edits.tribes` with config/main `chars`/`tribes`. Any difference = measured values are not the saved values → do not import/publish, tell the user to re-run "วิเคราะห์" then 💾 (pre-publish check ① in ops-rules).
- Import: read config/main with out_dir, then `node tools/apply-config.mjs <main.json> [overrides.json]` (values absent from config = unchanged · rarity change reprices per shop rules (V1.13) · skills if present = replace whole set · extraTribes replace extra tribes · cdMs milliseconds → seconds · overrides = skill edits the user decided · **cfg.tribes (V1.27) rewrites the matching lines of RULES.tribeBonus in core/rules.js, each field must be 3 numbers; line comments are kept and may become stale**) · keep a copy of the old characters.js first (for csv.mjs and rollback).
- Tribe bonus changes alter the game data hash → run `node lab/botgen.mjs` again (see botteams.md §13).
- **Game rules (V1.30, set 76):** config may carry `rules` = { RULE_SPEC path: value in stored units (ms for time) } from the "กฎเกม" tab. cfgcode.mjs rejects locked/unknown/out-of-range keys; apply-config.mjs merges them into `core/rules-user.js` (RULES_USER, merged into RULES at load) — never edit the RULES literal for these. Character prices follow RULES.shop.prices automatically. Pre-import check compares `rules` too.
- **No db access (second account, set 48):** user presses "คัดลอกค่าให้ Claude" (edited-values box) and pastes the `AMCFG1 …` code → save it to a file → `node tools/cfgcode.mjs <file> <out dir>` (validates; writes main.json; prints pre-import check MATCH/DIFFERS, exit 1 on DIFFERS) → `node tools/apply-config.mjs <out dir>/main.json` as usual. Clearing config/main afterwards is left to the owner account (or the next publish makes the page defaults = imported values, so yellow clears anyway). **Set 61:** the code also carries open ideas (status รอ Claude / ต้องเลือกก่อน, max 50) — cfgcode.mjs prints them as a list; answer them in chat (this account cannot write the `ideas` db; the user marks status on the page). Codes without `ideas` still work.
- ideas: (char, text, status, at, reply) · answer as reply + set status only to values the page knows: "รอ Claude" · "ใช้แล้ว" · "ต้องเลือกก่อน" · "ไม่ใช้".
- After every import (batch 35 · user chose): **always publish the Balance Room with the new values in the same batch** → page defaults = imported values → yellow badges/cells (edited values) clear themselves · values the user edits after 💾 stay yellow · **no need to change DRAFT_KEY** (only when Claude uses values different from what the user saved) · values compared by sorted field names (canon) so skill-field order never leaves yellow behind.
