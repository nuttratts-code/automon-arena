## 3. Risks to watch while porting (JS ≠ GDScript)
- 32-bit math: `Math.imul`, `>>> 0`, `|0` → GDScript ints are 64-bit; mask with `& 0xFFFFFFFF` and emulate imul.
- `Math.round` rounds .5 up (−0.5 → −0); GDScript `round()` rounds half away from zero (−0.5 → −1). Use a helper `js_round`. Core uses Math.round in 11 files.
- Sort: JS `Array.sort` is stable; Godot `Array.sort_custom` is not guaranteed stable → add an index tie-break everywhere (28 sort calls in core).
- Object key order (JS insertion order) vs Dictionary order — Godot also keeps insertion order, but check every `for…in` / `Object.keys` loop.
- Float division / `Math.floor` on negatives: same IEEE doubles, but check int vs float typing in GDScript (`5/2 == 2` for ints).
- Values drift between the two cores: only one source (exported game.json) + golden parity in CI on every push.
- Fonts: game page loads fonts from the web (build-plan V1.55) — embed a Thai font in Godot.
